# 制作复盘与提炼顺序

本轮依据：早期人物资产树与分镜工程、抽象情绪MV的原LRC恢复记录、批量制作失败复盘、连续长卷和冬日歌词的多轮样段、完整长卷及开场修订记录。具体素材和完整歌词均只保留本地。

## 已经形成的判断

| 实际问题 | 应沉淀的规则 |
| --- | --- |
| 把纯前奏误认成歌词错位 | 确认的原LRC优先；先查人声，不做无证据全局对齐 |
| 画风到后半段逐渐变化 | 全片共用风格锚点；开头、中段、尾声并排检查 |
| 小人物脸部模糊 | 资产卡与局部细节生成，按最终显示尺寸验收 |
| 连续走路难匹配脚底和地面 | 根据叙事选择独立局部故事；世界移动由后期可控摄影机完成 |
| 横排场景仍然割裂 | 相邻画面共享地理元素、尺度、色调与接缝区 |
| 字幕逐句浮现抢占注意力 | 让整组提前可读，当前行简洁标记，唱完渐隐 |
| 高亮、放大、扩散不合调性 | 小样比较，以实际画面判断；保存所选方案和拒绝原因 |
| 片头静止，正文才运动 | 开场也是场景；从首帧运动，接点匹配位置和速度 |
| 模型凭空增加树木或路人 | 缩小动作约束范围、检查实际帧，拒绝后返修 |
| 作品内容进入公共仓库 | 整个具体工程放本地；只提炼通用配方、代码和合成测试 |

## 必须保留的失败经验

曾有批量任务只生成少量计划镜头，渲染脚本却用静帧和循环填满时长，并将解码和帧数通过当作“完成”。本地复盘已经将这些结果判为拒绝，不能作为成功生产案例。

需要分别记录：计划镜头、真正生成的源、被编辑选中的源、缺失项、复用方式及审查结果。技术成功不代表故事、动态或画风合格。素材不足必须显式失败；有意使用定格或重复时，要在创作计划中写明。

## 这轮已落地

- 三种制作配方和项目内模板，通过CLI创建本地草稿。
- 音频、资产、生成、文字、摄影机、验收的制作手册。
- 工具能力状态表，区分可执行CLI与项目内已验证流程。
- 默认工程位置改为`projects/日期/工程名`，旧具体工程移出Git跟踪但保留本地。
- 初始化草稿无需伪造音频时长，进入制作后要求真实时长。
- 仓库测试改用合成数据，不依赖具体歌曲工程。

## 下一步按价值提炼

1. **统一选片表与生成执行器**：从多个局部运行脚本提炼提交、恢复、回执与拒绝管理；自动核对计划覆盖率，缺片禁止交付。验收是能从失败处继续、不会重复提交、能明确列出缺失镜头。
2. **共享世界合成器**：提炼场景、局部动作、摄影机、文字的世界坐标配置；摄影机路径与歌词布局分开。验收是不用改歌曲专属代码就能合成一段全新长卷，并验证接缝与首帧运动。
3. **可插拔字幕与片头**：电影双语字幕、场景中括号、片头署名三种组件；输入同一cue表，效果参数化。验收是换样式不重生成画面、不改原cue。
4. **统一交付检查**：复用音轨比对、逐帧布局、媒体解码、重复源统计和画面总览；报告明确已检查和未检查的范围。暗调、静态艺术镜头等使用作品相关策略。
5. **资产登记和可视化浏览**：身份、服装、姿势、场景、物件与来源可查询，记录已选与拒绝版本。先支持现有工程需要，再考虑更大的资产库。

下一支作品是检验配方和接口的机会。先让一条流程稳定地复用，再扩大批量，避免复制更多硬编码脚本。
